## 2. Detailed Principles Specification

### AP-01: Strict User Context Isolation
* **Statement:** The recommendation engine, feature store, and agentic workflows must enforce strict tenant and user-level isolation across storage, retrieval, and inference layers.
* **Business Rationale (Goal: CSAT ≥ 70%):** Cross-user data leakage or contaminated recommendations damages customer trust and degrades personalization relevance. Personalization must never expose or mix one customer's history or attributes with another.
* **Architecture Implications:**
  * Feature stores must use tenant/user IDs as mandatory partition keys.
  * Vector embeddings and Retrieval-Augmented Generation (RAG) queries must enforce user-level metadata filters (`user_id = $CURRENT_USER`).
  * In-memory cache entries for Next-Best Action predictions must have strict session/user boundaries.

---

### AP-02: Robust LLM Guardrails & Defense-in-Depth
* **Statement:** All interactions with Large Language Models (LLMs) and Autonomous Agents must pass through pre-execution input sanitization and post-execution output guardrails.
* **Business Rationale (Goal: Brand Safety & Automated Campaign Reliability):** Marketing copy and automated campaign actions generated by agents directly face customers. Malicious prompt injection, data extraction, or toxic hallucinations can cause severe brand and financial harm.
* **Architecture Implications:**
  * Implement an inbound guardrail layer to detect and block prompt injection, jailbreaks, and sensitive data probing.
  * Implement an outbound guardrail layer to verify that generated content complies with brand voice and does not leak system prompts or internal APIs.
  * Agentic marketing actions (e.g., launching an email/SMS blast or budget reallocation) must require explicit Human-in-the-Loop (HITL) approval thresholds.

---

### AP-03: Privacy by Design & PDPL Compliance
* **Statement:** All ingestion, storage, processing, and model training involving personal user data must comply strictly with the Saudi Personal Data Protection Law (PDPL) and global privacy standards.
* **Business Rationale (Goal: Regulatory Compliance & Zero Legal Liability):** Non-compliance with PDPL carries severe financial penalties and legal liability. Respecting consumer privacy choices reinforces brand loyalty and CSAT.
* **Architecture Implications:**
  * Personally Identifiable Information (PII) must be tokenized or masked before entering LLM contexts or vector indexes.
  * The system must implement consent management and support the "Right to Erasure" (purging user data across databases, feature stores, and vector indices).
  * Data residency requirements must be enforced; sensitive customer data must remain within approved sovereign cloud boundaries.

---

### AP-04: Elastic Scalability for Seasonal Campaign Surges
* **Statement:** The personalization pipeline and serving infrastructure must automatically scale to handle high-traffic promotional peaks without latency degradation or failure.
* **Business Rationale (Goal: Increase Sales Take-Rate by 80%):** Major sales events (e.g., Ramadan, White Friday, National Day) generate extreme traffic spikes. Dropped requests or slow page loads directly reduce conversion rates and sales take-rate.
* **Architecture Implications:**
  * Distinguish between two scaling dimensions:
    1. **Consumer-Facing Recommendation Serving:** Must handle horizontal auto-scaling with p95 latency under 100ms.
    2. **Internal Marketer Portal:** Scaled for administrative concurrency (e.g., 50–100 simultaneous marketing specialists managing workflows).
  * Decouple real-time recommendation inference from background feature ingestion using asynchronous message queues (e.g., Kafka / Cloud Pub/Sub).
  * Use multi-tier caching (Redis / CDN edge) to offload repeated queries during flash sales.

---

### AP-05: Zero-Trust API Security & Decoupled Architecture
* **Statement:** The frontend client and backend microservices must be completely decoupled, communicating exclusively via secure, authenticated, and rate-limited API gateways.
* **Business Rationale (Goal: High Availability & Perimeter Integrity):** Prevent unauthorized access, data scraping, and API abuse originating from the browser inspect tools or external bots.
* **Architecture Implications:**
  * No business logic, API keys, model credentials, or database secrets may exist in client-side code.
  * All ingress traffic must terminate at an API Gateway enforcing JWT authentication, Role-Based Access Control (RBAC), and DDoS/Rate Limiting.
  * Internal service-to-service communication must use mutual TLS (mTLS) and private virtual network boundaries.
